## 一、代码侧已完成

### 新增探针 `GET /healthz`

不监控首页 —— 因为首页首屏 HTML 只有「加载中…」，而 UptimeRobot **不执行 JavaScript**，监控它只能证明"HTML 文件能下发"，证明不了内容在更新（用关键字监控首页会永远通过，形成**假绿**）。

所以新增了一个由服务端判断新鲜度的探针：

| 状态码 | 含义 | 监控端结果 |
|---|---|---|
| `200` | 应用在跑，且最近一次成功更新在 **8 小时**内 | up |
| `503` | 应用在跑，但内容已陈旧（抓取循环失效 / 信息源全被挡） | down |
| 无响应 | 隧道断、进程死、机器关机 | down |

一个 monitor 同时覆盖**「挂了」和「静默停更」**两种故障。

响应示例（真实线上响应）：

```json
{"last_update":"2026-11-06 08:22:00","max_stale_hours":8,"hours_since":3.5,"ok":true,"reason":"fresh"}
```

`reason` 的取值：

| reason | 含义 |
|---|---|
| `fresh` | 正常 |
| `stale` | 超过 8 小时没成功更新 → **这是会告警的那种** |
| `no_update_record` | 数据库里没有 `last_update`（全新库 / 误删） |
| `unparsable_timestamp` | 时间串坏了，数据异常 |
| `db_error` | 数据库读不出来 |
| `clock_skew` | 时间戳在未来（时钟回拨），按健康处理，避免误报 |

### 阈值为什么是 8 小时

`config.yaml` 的策略是「距上次成功更新 > 4 小时就刷新」，检查间隔 30 分钟，所以健康状态下两次更新的最大间隔约 **4~4.5 小时**。取 8 小时 = 留一倍余量：既不会因为一次慢更新误报，也不会容忍真正的停更。

要改就改 `app/api.py` 顶部的 `HEALTH_MAX_STALE_HOURS`。

### 已验证

```powershell
python docs\audit\check_healthz_live.py  # 线上验收：走 Cloudflare + 隧道打一次，退出码 0 才算可挂监控
```

## 二、你要做的（约 5 分钟）

1. 打开 <https://uptimerobot.com/> → 注册（免费，**不需要信用卡**）
2. 登录后点 **Add New Monitor**
3. 按下表填：

| 字段 | 值 | 说明 |
|---|---|---|
| **Monitor Type** | `HTTP(s)` | 不要选 Keyword |
| **Friendly Name** | `InfoRadar` | 随便 |
| **URL** | `https://inforadar.xin/healthz` | **注意结尾是 `/healthz`** |
| **Monitoring Interval** | `5 minutes` | 免费版上限 |
| **Alert Contacts** | 勾选你的注册邮箱 | 免费版只能用邮箱 |
| **Advanced → 判定规则** | 2xx 为 up，其余为 down | 默认即如此；503 会被判为 down |

4. 保存。UptimeRobot 会立刻检测一次，30 秒内你会在仪表盘看到 **Up**。

## 四、收到告警后怎么查（对照表）

| 现象 | 大概率原因 | 处理 |
|---|---|---|
| 完全打不开，CF 返回 **1033** | 隧道没连上（进程死了 / 没开机 / QUIC 被干扰） | ① 看 `Get-Process cloudflared` ② 起来后跑 `cloudflared tunnel info inforadar` ③ 若 QUIC 超时，确认 `config.yml` 里有 `protocol: http2` |
| CF 返回 **502** | 隧道在，但 `127.0.0.1:7100` 没监听 | 看 `Get-Process pythonw`，重启应用 |
| 页面能开，但 `/healthz` 是 **503 + stale** | 应用活着但抓取循环没跑成 | 看 `docs/audit/app-err.log`；手动 `POST /api/update` 触发一次；检查各源是否被 WAF 挡（日志里会有 `部分失败`） |
| `/healthz` 503 + `db_error` | 数据库坏了/被锁 | `sqlite3 data/radar.db "PRAGMA integrity_check;"` |
| 一切正常但没收到恢复邮件 | 免费版不支持"重复/持续通知" | 恢复邮件仍会发；只是不会反复提醒 |

## 五、这件事治"瞎"，不治"死"

| | 作用 |
|---|---|
| **监控（本文）** | 站挂了，你 10 分钟内知道 |
| **迁移上云（`迁移指南.md`）** | 站不再依赖你的笔记本，不会挂 |

两个都要。先做监控，因为**做了上云但没做监控，你在云上挂了照样不知道** —— 而且云服务器你更不会天天看。
