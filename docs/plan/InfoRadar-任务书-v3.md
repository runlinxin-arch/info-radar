## 一、定位与目标

**现状**：一个实时滚动窗口 —— 内容平均 6.5 小时就永久消失，没有文章级 URL，首屏 HTML 为空。
因此它**不能被搜索、不能被分享、不值得回访**。

**目标（一句话）**：把它从「实时滚动窗口」变成**可积累的资讯档案** ——
内容留得住、每条有地址、首屏有正文、能被搜索与分享。

## 三、核心判断

这个站现在**不产生任何可积累的资产**，三个维度同时缺失，而且互相强化：

```
内容活 6.5 小时
   ├─ 时间积累缺失 → 没有历史 → 没有回访理由
   ├─ 链接积累缺失 → 分享出去的链接第二天 404 → 传播链断裂
   └─ 索引积累缺失 → 首屏空壳 → 搜索引擎手里没有可索引内容
                        └─ 没有流量 → 没有动力补历史
```

**「依赖单机常驻」是放大器**：任何积累都可能被一次合盖/断网清零（历史最长静默 38 天）。

**而且几乎没人在用**：Cloudflare Web Analytics 显示过去 24 小时只有 **7 次访问 / 7 次浏览**
（这是接入统计后的第一个真实基线）。在这个量级下，任何「体验优化」都无从验证 ——
所以本任务书把「积累」排在「体验」之前。

结论：**先解决「积累」，再谈体验与增长。**

## 十、工作规则（沿用 v2 中仍有效的部分）

1. **改配置当场验证**：任何配置修改后立刻用权威通道确认生效。
2. **分阶段交付**：每个里程碑完成后汇报，等确认再进下一个。
3. **版权红线**：`fetch_full_content` 保持 `false`；只展示摘要 + 原文链接 + 来源署名。
4. **失败诚实**：卡住就报失败原因，不给「应该没问题」这类无验证结论。
5. **可回滚**：改动前先能说清怎么退回去。
6. **文档随代码更新**：改动后跑 `verify_report_claims.py`，退出码非 0 即文档与代码不一致。
